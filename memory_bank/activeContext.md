## Модуль «Информатика — ОГЭ» `/math` — фикс CSS (2026-08-20, итерация 3)

**Проблема (жалоба пользователя):** после перевода страницы на паттерн `.replace` слетело форматирование/CSS.

**Причина:** CSS-блок остался с f-string экранированием `{{ }}` (оно нужно только внутри `f"""..."""`). После перехода на обычную `"""..."""` браузер получал буквально `* {{ margin: 0; ... }}` — невалидный CSS.

**Фикс:** в блоке `<style>` страницы `/math` заменены все `{{` → `{` и `}}` → `}` (44 строки). В тест `test_math_page_renders` добавлены проверки `assert "* {{ margin" not in body` и `assert "* { margin" in body`.

**Проверки:** 38 passed, ruff clean, compile OK, `/math` → 200 локально и на проде. Закоммичено `7386f6b`, задеплоено.

**⚠️ Грабли (важно):** при переводе страницы с `f"""..."""` на обычную `"""..."""` (или наоборот) — обязательно проверять весь HTML-блок: CSS `{{ }}` нужен только во f-string; JS-шаблоны `` `${...}` `` во f-string надо писать как `\${...}`. Надёжнее использовать обычную строку + `.replace()` (паттерн `/emperors`) и НЕ использовать `{{ }}` вовсе.

- **Диагностика:** добавили временные `print`-ы в `api_achievements_activity` и `_unlock_achievements` → логи Vercel показали:
  - `[ACH-DBG] uid=8 module=emperors newly=[] counts={'emperors': 73, ...} ach_count=2` — условия выполнялись, но вставка не шла.
  - `UniqueViolation` на `first_step` (уже открыт) → в PostgreSQL после ошибки транзакция **абортится** → все следующие `INSERT` падают с `InFailedSqlTransaction` → `newly=[]` для ВСЕХ.
- **Root cause:** `_unlock_achievements` рассчитывал на UNIQUE-индекс для дедупликации, но в PostgreSQL первый `UniqueViolation` валит всю транзакцию. В SQLite (тесты) такого нет — поэтому локально/в тестах всё проходило.
- **Фикс:** `_unlock_achievements` теперь **сначала читает уже открытые коды** (`SELECT code FROM web_achievements WHERE user_id=:id`), пропускает их и только потом вставляет новые. Ранее добавленные `conn.commit()` после `_check_web_achievements` в activity/daily_prayer — безвредны, оставлены.
- **Проверка:** на проде через токен пользователя `POST /api/achievements/activity` открыл сразу 13+ ачивок (`emperors_first`…`emperors_50`, `first_quiz`, `first_streak`, `streak_3`, `days_3`, `module_2`, `first_50_actions`, `chess_first`, `prayer_first`, `coins_10`); итого 17 открыто, монет 170. Повторный вызов → `unlocked: []` (дедупликация работает).
- **Тесты:** `test_achievements.py` + `test_web_portal_e2e.py` → **17 passed**; ruff clean; задеплоено на прод.
- **Вывод:** в `api/index.py` при использовании PostgreSQL нельзя полагаться на UNIQUE-индекс для дедупликации в цикле вставок — первая же ошибка абортит транзакцию. Проверять наличие до INSERT.
