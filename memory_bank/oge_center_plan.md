# OGE Center — план подготовки к ОГЭ по 5 предметам

**Создан:** 2026-08-24. **Дедлайн:** ОГЭ через год (май–июнь 2027).
**Предметы:** математика, русский язык, информатика, физика, история.
**Канонический список задач:** `projectbrief.md` → Phase 6 (OGE-00…OGE-06 + OGE-FULL).

## Утверждённые решения

1. **URL:** информатика переезжает `/math` → `/informatics` (redirect со старого пути), математика занимает `/math`. Пакет `core/math/` → `git mv core/informatics/`, обновить импорты (`api/index.py:10570`) и `tests/unit/test_math_module.py`.
2. **Единая таблица прогресса** `study_progress` для всех 5 предметов; императоры мигрируют в неё.
3. **Контент:** сначала MVP (~50–100 позиций на предмет), затем OGE-FULL — добить весь кодификатор ФИПИ (зафиксировано пользователем как следующий шаг).
4. **Русский:** тестовая часть + чек-листы изложения/сочинения по критериям ФИПИ (без автопроверки).

## Ядро рекомендаций (OGE-00) — «система сама предлагает, что учить»

### Таблица `study_progress`
```
user_id INTEGER NOT NULL
module TEXT NOT NULL        -- 'history'|'informatics'|'math'|'russian'|'physics'
card_key TEXT NOT NULL      -- history: 'type::text'; новые: 'formula::id', 'task::id', 'rule::id'
reps INT DEFAULT 0
interval_days REAL DEFAULT 0
ease REAL DEFAULT 2.5
due REAL                    -- timestamp следующего показа (SM-2)
streak INT DEFAULT 0        -- серия правильных ответов подряд
correct_count INT DEFAULT 0
wrong_count INT DEFAULT 0
counter INT DEFAULT 0       -- legacy для истории
updated_at REAL
UNIQUE(user_id, module, card_key)
```

### API
- `GET/POST/reset /api/study/progress` — один эндпоинт на все предметы. POST принимает `{module, cards: {key: rec}}`. По образцу `/api/emperors/progress` (api/index.py:11204–11290): `_get_session_user(_auth_token_from_request())`, анонимам 401.
- `/api/emperors/progress` оставить тонким алиасом на общий API (module='emperors' → 'history') на переходный период.

### Миграция императоров
В `_ensure_study_progress_tables()` — идемпотентный перенос: если в study_progress нет строк с module='history', скопировать INSERT … SELECT … ON CONFLICT DO NOTHING из emperors_progress.

### Планировщик `/api/study/recommendations`
Приоритет выдачи:
| Приоритет | Что | Источник |
|---|---|---|
| 🔴 | Просроченные карточки (`due < now`) | SM-2 во всех модулях |
| 🟠 | Слабые темы (% ошибок > 40%) | wrong/correct по card_key |
| 🟡 | Новые темы предмета, не начатые | отсутствие записей |
| ⚪ | Вес предмета ↑ по близости даты ОГЭ | даты экзаменов в конфиге |

Ответ: топ-N действий `{subject, action, count, reason, url}`.

### Хаб
Виджет «📌 План на сегодня» (топ-5 рекомендаций со ссылками вида `/emperors?algo=flash`) + бейджи с числом просроченных на карточках предметов. Каждый модуль пишет ответы в общий API → рекомендации обновляются сами.

### Даты ОГЭ (конфиг, редактируемые)
Примерные даты июня 2027 по предметам; используются планировщиком для весов.

## Конвейер нового модуля (отработанный паттерн)

data-пакет `core/<subject>/` (frozen dataclasses, stdlib-only, образцы: `core/history/emperors.py`, `core/math/tasks.py`) → страница по скелету `math_page` (api/index.py:10567–11030: route → json.dumps → HTML с `__PLACEHOLDER__` → `.replace()` chain) → запись ответов в `/api/study/progress` → ачивки (COUNT-факт ~строка 1523, записи ACHIEVEMENTS ~1243, пороги ~1755) → тест `tests/unit/test_<subject>_module.py` (данные + test_client GET без плейсхолдеров + API с patch get_db_engine/_get_session_user/_auth_token_from_request) → карточка в хабе (~4625).

**Грабли:** JS страниц проверять `node --check` (извлечение `<script>` блоков regex); ruff после каждого файла; деплой `$env:VERCEL_CLI_NO_ANALYTICS="1"; vercel --prod --yes`.

## Этапы и содержание предметов

### Этап 0 = OGE-00 (ядро)
Сначала ядро, потом предметы. См. выше.

### Этап 1 = OGE-01 Математика (обязательный предмет — первым)
- Карточки формул ~130: сокращённое умножение, квадратные уравнения/дискриминант, прогрессии, степени/корни, тригонометрия прямоугольного треугольника, площади фигур, теорема Пифагора, подобие, средняя линия, вероятность/статистика, единицы измерения.
- Генераторы параметрических задач (случайные числа → бесконечная тренировка): проценты, текстовые задачи (движение/работа/смеси), координатная плоскость, чтение графиков.
- Режимы: карточки SM-2, задачи по темам, экзамен-режим (25 заданий, оценка по шкале ОГЭ).

### Этап 2 = OGE-02 Информатика (расширение)
Темы к существующим 9: системы счисления (+генератор переводов 2/8/16↔10), кодирование и объём информации, логика (таблицы истинности), графы/деревья, электронные таблицы, файловая система, адресация сети. Итог ~17 тем / ~120 задач. Серверный прогресс подключить.

### Этап 3 = OGE-03 История (дополнение)
- `TERMS` ~80 терминов ОГЭ (опричнина, рекрутчина, отрезки…) с определениями; режим «термин↔определение» (flashcards) на существующей странице.
- Культура: дополнить PERSONS культурными деятелями.
- Переход на общий движок прогресса.

### Этап 4 = OGE-04 Русский
- Карточки правил: НН/Н, НЕ/НИ, слитно/раздельно, пунктуация (ССП/СПП/ДСП, обороты, однородные), части речи, грамматические нормы.
- Тестовые задания формата ОГЭ: орфографический/пунктуационный/синтаксический анализ, текстоведение.
- Раздел «Изложение и сочинение»: критерии ФИПИ, структура, клише — чек-листы без автопроверки.

### Этап 5 = OGE-05 Физика
- Шпаргалка формул по разделам: механика (кинематика/динамика/статика), давление и газы, работа/энергия, тепловые явления, электричество, магнетизм, оптика, квантовая.
- Карточки «формула↔величина↔единица СИ» (matching-режим).
- Простые расчётные задачи с вводом числового ответа.

### Этап 6 = OGE-06 Полировка
Экзамен-режимы везде (таймер, шкала оценок ОГЭ), ачивки по всем предметам (пороги «освоено N»), статистика слабых тем на каждой странице.

### OGE-FULL
Добить весь кодификатор ФИПИ по всем 5 предметам после MVP (следующий шаг после этапов 1–5, зафиксировано пользователем).

## Порядок работ при исполнении каждого этапа

2. Реализация по конвейеру
3. Проверки: ruff → pytest (новый + регресс) → node --check JS → смоук test client
4. Коммит + push + deploy + проверка прода
5. Обновить статусы deliverables в `projectbrief.md`, Changelog в `progress.md`, `last_checked_commit`
