## Архитектурное ограничение (зафиксировано до реализации)

Полноценный LSP-демон (`jedi-language-server`, `pyright` через stdio) на Vercel **невозможен**: лямды stateless, персистентного процесса между запросами нет, жёсткий лимит `maxDuration = 60` (`vercel.json:4`). In-process `jedi` — это тот же движок, что использует IPython, и максимум, достижимый в этих условиях.

Если в будущем появится постоянный рантайм (self-hosted VPS), замена сводится к замене `_pyed_script()` на прокси к LSP — контракт эндпоинтов менять не придётся.

## Конвейер нового модуля (отработанный паттерн)

`api/index.py`: секция `# ── Python Editor ──` между `/code` и `/md2pdf` → DDL-функция рядом с остальными `_ensure_*` (вызов из `get_db_engine()` в `try/except` + `log_error("PYED", ...)`) → эндпоинты `def api_pyed_*()` + тонкие `@app.route`-обёртки → страница как необработанная строка с `__PLACEHOLDER__`-заменой (без f-string, иначе все JS-скобки пришлось бы удваивать) → карточка в хабе + ключ в `HUB_KEY` → `tests/unit/test_python_editor.py` на SQLite `StaticPool` → `node --check` по отрендеренному `<script type="module">` → ruff → коммит кода → коммит памяти → push → деплой → прод-смоук.

## Грабли, за которые уже заплачено

- **DML-таймстемпы:** `NOW()` работает в Postgres, но **не в SQLite** → в `UPDATE` используется `CURRENT_TIMESTAMP` (совместимо с обоими). `_ddl()` переписывает только DDL, не DML.
- **Тип `user_id`:** `INTEGER`, чтобы совпадать с `web_users.id` (SERIAL) — тогда админ-эндпоинт удаления аккаунта (`8e8da1b`, скан user-колонок через `information_schema`/`PRAGMA`) удаляет и файлы редактора. Для TEXT-колонок он ищет хеш `_web_user_id("u<id>")`, поэтому «просто TEXT» здесь не сработало бы без проверки.
- **DDL в рамках Cold Start:** каждая `_ensure_*` выполняется на каждом холодном старте; `"info"`-лог в Telegram не уходит (в `log_error` есть `if error_type != "info"`), а вот реальная ошибка DDL — уйдёт, и это правильно. Не вызывать DDL вне `_ensure_*`.
- **`ok` в ответе `/run`** нельзя хардкодить: `ok = not stderr`. Ошибка была поймана тестом `test_run_reports_stderr`.
- **Проверка JS:** извлекать `<script type="module">` из **отрендеренного** HTML через `app.test_client().get('/editor')`, а не из исходника `api/index.py` — в исходнике `\\s` ещё не разэкранирован и `node --check` даёт ложную ошибку.
- **Деградация обязательна:** CodeMirror с CDN. Школьная сеть может не пустить `esm.sh` → `try/await import` падает → откат на `<textarea>`, сохранение и запуск продолжают работать. То же с `jedi`: ленивый импорт + `degraded: true`.

## Принятые решения по безопасности

- Публичная кнопка «Запустить» выполняет произвольный код → авторизация + DB-лимит + `_sandbox_preexec` (CPU/память/файлы/дескрипторы) + обрезка вывода 8000 символов + лимит буфера 150 КБ.
- AST-блок-лист (`_BLOCKED_MODULES`, `_BLOCKED_KEYWORDS`) не менялся: это общий контракт с `/api/ai_chat`.
- Сетевой egress и `PATH` в песочнице не ограничены (существующее ограничение). Полноценное закрытие — контейнер/микро-VM, что невозможно на текущем плане хостинга.

## Что осталось за рамками (предложено пользователю, не сделано)

`/api/ai_chat` (`api/index.py:11293`) вызывает `_tool_run_python` **без авторизации** — только IP-лимит 15/мин. Анонимный посетитель может выполнять произвольный Python на сервере. Закрыть: требовать сессию + добавить rlimit к вызову из AI-чата.
