# lthub-tunnel — доступ к сайту из РФ

Сайт живёт на Vercel (`lthub.vercel.app` + `audioservice.vercel.app`), а домены
`*.vercel.app` в России фильтруются. Инструмент поднимает **локальный прокси
sing-box** из обычной VPN-подписки и открывает сайт в браузере, который ходит
только через этот прокси.

Никаких TUN-драйверов и прав администратора: `mixed`-инбаунд на
`127.0.0.1:2080`, который понимает и HTTP, и SOCKS5.

самопроверка не прошла, релиз не публикуется.

## Приложение (окно)

Обычный запуск — двойной клик по готовому файлу (из Releases либо после
локальной сборки):

```
scripts/lthub_tunnel/dist/LthubTunnel.exe
```

Всё в одном: код, `sing-box` и подписки. Python на компьютере не нужен.

Окно простое: большая кнопка **Подключить**, статус (отключено / подключение /
подключено), кнопки «Открыть сайт» и «Выход», внизу лог — что скачалось, сколько
нод ответило, какая лучшая. Закрытие окна гасит прокси.

Свой файл подписок можно положить рядом с `.exe` под именем
`sources.local.json` — он имеет приоритет над встроенным.

Запуск из исходников (когда правки в коде, а не в бинарнике):

```powershell
python -m scripts.lthub_tunnel.gui
```

Пересобрать `.exe` после правок:

```powershell
pip install pyinstaller
python scripts\lthub_tunnel\build_exe.py
```

Проверить, что собранный бинарник вообще работает (окно не нужно, всё пишется в
лог):

```powershell
scripts\lthub_tunnel\dist\LthubTunnel.exe --selftest C:\Temp\lthub.log
```

## Установка

```powershell
python -m scripts.lthub_tunnel.tunnel install
```

Скачивает `sing-box` (1.14.2) в `scripts/lthub_tunnel/bin/` (папка в `.gitignore`).
Для сборки `.exe` это происходит автоматически при первой кнопке «Подключить».

## Источники подписок

Создать `scripts/lthub_tunnel/sources.local.json` (закоммичен — внутри
публичные VPN-конфиги, секрета нет):

```json
{
  "urls": ["https://.../subscription/..."],
  "probe_url": "https://lthub.vercel.app/api/ping",
  "port": 2080
}
```

Поддерживаются и base64-подписки, и «голый» текст со строками `vless://`.
Можно переопределить из CLI: `--source <url>` (можно дважды).

## Запуск на Windows

Из корня репозитория, в PowerShell:

```powershell
python -m scripts.lthub_tunnel.tunnel up --open
```

Появится окно с прокси, откроется Edge, и всё заработает. Закрыть — `Ctrl+C`
в этом окне.

Если в консоли вместо русского текста идут знаки вопроса, это старая кодировка
Windows-консоли:

```powershell
chcp 65001
```

**Про зависание.** Первый запуск занимает 20–40 секунд и это нормально: тянется
подписка, пингуются ~100 нод, sing-box проверяет конфиг и замеряет сквозную
задержку (`--settle`). Дальше пинг занимает секунды. Если кажется, что всё
зависло, добавь `--no-ping` (сборка без пинга) или посмотри лог:

```powershell
python -m scripts.lthub_tunnel.tunnel up --no-ping --settle 0
```

**Фоновый запуск** (для скриптов и ярлыков) — туннель живёт, пока жив sing-box:

```powershell
Start-Process python -ArgumentList "-m","scripts.lthub_tunnel.tunnel","up","--open" -WindowStyle Hidden
```

Остановить потом — `Stop-Process -Name sing-box`.

## Команды

| Команда | Что делает |
|---|---|
| `ping` | скачивает подписки, меряет задержку каждой ноды, печатает рейтинг |
| `build` | скачивает подписки, пингует, собирает `config.json`, печатает статистику |
| `check` | `build` + вердикт `sing-box check` |
| `up` | поднимает прокси, проверяет сайт, ждёт Enter |
| `up --open` | то же + открывает сайт в Edge с прокси и отдельным профилем |
| `export` | выгружает конфиги для пользователей (sing-box / Clash) |
| `install` | скачать sing-box |

Полезные опции (идут **после** имени команды):

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--top N` | `10` | сколько самых быстрых нод оставить в конфиге (`0` — всех живых) |
| `--ping-timeout S` | `3.0` | таймаут пинга одной ноды |
| `--no-ping` | выкл. | не пинговать, собрать из всех нод |
| `--only n7` | — | оставить одну ноду (отладка) |
| `--limit N` | — | взять первые N нод |
| `--site URL` | `https://lthub.vercel.app` | какой сайт проверять |
| `--state-dir PATH` | `%LOCALAPPDATA%\lthub-tunnel` | где хранить конфиг, логи и кеш |

## Как выбирается нода

Отбор двухступенчатый, и это важно понимать:

1. **Пинг** (`probe.py`) меряет TCP-коннект + TLS-хендшейк с SNI. Он
   параллельный, поэтому ~100 нод проверяются за секунды, и ни один туннель
   при этом не поднимается. Мёртвые адреса отсеиваются, живые сортируются, в
   конфиг попадают `--top` самых быстрых.
2. **Сквозную задержку** меряет сам sing-box в группе `urltest` — уже через
   туннель, с настоящим протоколом. Он же держит победителя, пока прокси жив,
   и уходит на другую ноду, когда текущая умирает.

Одного пинга мало: адрес может принимать соединения, а прокси через него — нет
(например, за CDN с неверным SNI). Поэтому пинг — это фильтр и порядок, а
окончательный выбор всё равно за `urltest`.

Если не ответил никто, конфиг собирается из всех нод: чужая сеть не должна
ломать запуск.

## Если сайт не открылся

1. `python -m scripts.lthub_tunnel.tunnel up` — посмотреть, что пишет.
2. `python -m scripts.lthub_tunnel.tunnel ping` — есть ли живые ноды вообще.
3. Свободные ноды умирают: перезапустить.
4. Проверить конкретную ноду: `--only n7` (список с пингами — в `nodes.tsv`).
5. Лог sing-box — в `<state-dir>/sing-box.log`.

Известная особенность некоторых сетей: DNS отдаёт адрес Vercel, по которому
соединение сбрасывается, а с явным `--resolve` на рабочий edge-IP сайт отвечает
мгновенно. В этом случае лечится hosts-запись, а не туннель.

`--state-dir` по умолчанию `%LOCALAPPDATA%\lthub-tunnel`.

## Подписки и кеш

Каждая удачная загрузка подписки сохраняется в `<state-dir>/subs/`. Если
источник временно недоступен (Vercel периодически рвёт соединение на холодном
старте), используется последняя удачная копия — с пометкой `(из кеша)` в выводе.
Пинг всё равно отсечёт ноды, которые за время простоя умерли.

Имя файла кеша — хост плюс хеш URL, так что токен подписки на диск не пишется.

Источники перечислены в `sources.local.json` (закоммичен, это публичные
VPN-конфиги из интернета):

```json
{
  "urls": ["https://host/feed1", "https://host/feed2"],
  "probe_url": "https://lthub.vercel.app/api/ping",
  "port": 2080
}
```

Подойдёт любой из трёх видов ответа: base64 со ссылками `vless://`/`trojan://`,
голый текст со ссылками построчно (так отдают гитхак-подписки) или смесь обоих.
Источники качаются **параллельно**, недоступные пропускаются — достаточно
одного рабочего; прогресс по каждому виден в логе (`[1/3] Скачиваю …`,
`ok`, `пропущен`).

**Сколько ждать.** Таймаут скачивания — 15 с на попытку, повторов 3, и важно:
повторяется только сетевой сбой, а не перебор User-Agent. Менять User-Agent
имеет смысл лишь когда ответ пришёл, но оказался не подпиской. Поэтому источник
с битым сертификатом отваливается за секунды, а не за минуты.

**Кеш экономит время, а не только нервы:** пока на диске есть последняя удачная
копия, бюджет на сеть — ровно **одна** попытка (сеть легла → сразу кеш), а
полный цикл повторов отрабатывает только когда кеша ещё нет. Источники
независимы, поэтому суммарное время — это самый долгий из них, а не сумма
всех: три источника из которых один мёртвый занимали 145 с, стали занимать
10–26 с.

## Android

Свой APK не нужен — конфиги выгружаются командой:

```powershell
python -m scripts.lthub_tunnel.tunnel export --out dist
```

- `dist/lthub-clash.yaml` — импортируется в Mihomo / Clash Meta GUI и v2rayNG.
- `dist/lthub-sing-box.json` — конфиг для sing-box-android / SagerNet.
- `dist/lthub-nodes.tsv` — список нод с пингами, если нужно разбираться руками.

В выгрузку попадают только живые и самые быстрые ноды: раздавать телефон
десятки заведомо мёртвых бессмысленно.

## Как это устроено

1. `subscriptions.py` скачивает подписку с повторами и ретраями, распаковывает
   base64, режет на строки, кеширует последний удачный ответ.
2. `nodes.py` превращает каждую строку в outbound sing-box и умеет объяснять,
   почему нода не годится (`xhttp`, reality без `pbk`, грязный `host`).
3. `probe.py` пингует ноды и оставляет самые быстрые.
4. `sbconfig.py` собирает конфиг: `mixed`-inbound + группа `urltest`.
5. **Самочистка**: одна плохая нода рушит весь конфиг sing-box, поэтому
   `prune_config()` по сообщению `sing-box check` выкидывает негодя и повторяет
   проверку, пока конфиг не станет валидным.
6. `tunnel.py up` ждёт первый замер `urltest`, затем открывает сайт через
   прокси с несколькими попытками.

## Windows

```powershell
python -m scripts.lthub_tunnel.tunnel up --open
```

Откроется Edge с `--proxy-server=http://127.0.0.1:2080` и отдельным
`--user-data-dir`, так что личные сессии не затрагиваются. Через тот же прокси
автоматически идёт и `audioservice.vercel.app` — отдельные настройки не нужны.

## Ограничения

- **`xhttp` не поддерживается** sing-box 1.14.2 (проверено `sing-box check`),
  такие ноды отбрасываются — обычно это ~10–15% списка.
- **Один битый источник не роняет всю работу:** источники проверяются по очереди,
  недоступные пропускаются с предупреждением. Типичные причины — сертификат
  выдан не на тот хост (`CERTIFICATE_VERIFY_FAILED`) или сервер не отвечает
  по IPv4.
- Свободные ноды живут минутами. Надёжность даёт не конкретная нода, а группа
  `urltest` с переподключением раз в минуту.
